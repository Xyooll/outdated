# Economic Priority

Operation DNA is optimized first for increasing productive capital while preserving survival and optionality.

## Priority

1. Increase productive capital.
2. Preserve capital and system survivability.
3. Reinvest only when expected leverage justifies it.
4. Increase automation and capability.
5. Scale infrastructure when measured workload or expected return warrants it.
6. Expand into additional nodes and applications as economics support them.

## Capital allocation loop

```text
Opportunity discovery
      ↓
Evidence
      ↓
Expected return / capital required
      ↓
Risk + downside + reversibility
      ↓
Smallest viable experiment
      ↓
Measure outcome
      ↓
Learn
      ↓
Reinvest / reject / scale
```

## Infrastructure rule

Infrastructure is an expense until it creates measurable leverage. The system should prefer the least expensive infrastructure that reliably supports the current workload, then scale from measured demand or demonstrated economic return.

## Growth metrics

Track, where applicable:
- available capital
- deployed capital
- expected return
- realized return
- risk-adjusted return
- capital efficiency
- revenue
- operating cost
- automation leverage
- cost per useful outcome
- infrastructure utilization
- infrastructure cost as a percentage of productive output

No application may interpret this priority as permission to bypass authorization, safety, legal/compliance requirements, or evidence thresholds.
