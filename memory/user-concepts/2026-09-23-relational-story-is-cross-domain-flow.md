# User Concept — Relational Story Is a Cross-Domain Flow

Date: **2026-09-23**  
Status: **ACTIVE / CORE FLOWARE ARCHITECTURE**

## USER-STATED CONCEPT

The story/character/relationship/memory/audit architecture should not belong only to the stock-market domain.

It should be usable in other layers and domains as a Flow in itself.

## CANONICAL INTERPRETATION

Promote the reusable structure into core Floware:

`floware/core/relational-story.flow.md`

The core architecture includes:
- root/main character;
- material characters;
- relationship-edge state;
- local webs;
- wrappers/pointers;
- evidence/source authority;
- canonical Character Memory;
- root-relative Story Memory;
- re-rooting;
- resource-bounded recursive expansion;
- state-change and miss audit.

Domains provide their own semantics.

## STOCK-MARKET CONSEQUENCE

The existing stock story flows are now specializations/adapters of the core Relational Story Flow.

The stock domain currently defines:
- stock/company character types;
- shareholder/economic propagation;
- stock evidence hierarchy;
- four-degree resource horizon;
- story → thesis → rhythm/window → payoff → strategy output.

## CORE PRINCIPLE

> **The network architecture is reusable; the meaning of the nodes, edges, evidence, and outputs belongs to the active domain.**
