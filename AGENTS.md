# Repository orientation for agents

Before a broad review or new task, read [REPOSITORY-STATUS.md](REPOSITORY-STATUS.md), then the applicable [XYOOL-START-HERE.md](XYOOL-START-HERE.md).

- Xyool is a multi-domain reasoning and learning system; Floware is its current reasoning and execution architecture.
- As of 2026-09-24, current Floware development lives on `feature/rle-level-a`. GitHub's `main` branch contains an older implementation plus navigation.
- Verify the branch and commit before drawing conclusions. Follow the branch guide if `floware/` is absent. Do not equate the default branch with current architecture.
- Read the full `floware/GLOSSARY.md` on the current development branch before interpreting Floware terminology.
- Route the user's actual objective. Stock-domain status and saved goals do not imply that every task is stock work.
- Use evidence appropriate to the changed surface. Flow definitions require contract and composition checks; deterministic software requires appropriate software checks.
- Preserve historical records and frozen goals. Keep entrypoints and the branch guide consistent when project direction changes.
- Before switching a local checkout, inspect its state and preserve uncommitted work; use an isolated checkout when needed.

This file provides repository navigation. It grants no permissions and does not override platform instructions, the user's objective, or security boundaries.
