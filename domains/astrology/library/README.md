# Astrology Domain Library

Status: **ACTIVE EXPERIMENTAL DOMAIN KNOWLEDGE MEMORY**

Contract:
`../../../floware/DOMAIN-LIBRARY-CONTRACT.md`

Purpose: give Astrology work a reusable, source-traceable starting state before outside research is repeated.

## Rule

~~~text
ASTROLOGY QUESTION
→ CHECK THIS LIBRARY
→ LOAD CANONICAL RULE / SOURCE / VALIDATION POINTERS
→ CHECK SCOPE + FRESHNESS + STATUS
→ RESEARCH ONLY MISSING / STALE / CONFLICTED PARTS
→ UPDATE CANONICAL ASTROLOGY ARTIFACTS
→ DISTILL REUSABLE KNOWLEDGE BACK HERE
~~~

This library does **not** replace:
- `../RULE-REGISTRY.md`;
- `../SOURCE-REGISTRY.md`;
- `../VALIDATION.md`;
- `../ESTABLISHMENT.md`;
- `research/` experiment records;
- private subject/chart state.

It indexes and distills them.

## Privacy

Do not store private birth data or subject-specific sensitive records in this general library.

Subject-specific state belongs only in an explicitly authorized private/state surface.

## Current maturity

The library is small by design.

It should grow from:
- established rule cohorts;
- validated/rejected hypotheses;
- recurring failure boundaries;
- reusable calculation/interpretation lessons;
- historical/prospective cases that are safe and appropriate to preserve;
- open questions that prevent repeated rediscovery.


## Indexes

Use:
- `INDEX.md` — reusable knowledge entries;
- `SOURCE-INDEX.md` — canonical source pointers;
- `RULE-INDEX.md` — canonical rule/ruleset pointers;
- `VALIDATION-INDEX.md` — validation/null/scoring/preregistration pointers.

These indexes are navigation layers, not duplicate authorities.
