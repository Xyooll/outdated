# Numerical Magic Domain — Run Sequence

Status: **CANONICAL OPERATING SEQUENCE v1.1**

Use one of two modes.

## Mode A — Decode an existing number or glyph expression

```text
1. FREEZE INPUT
2. DECLARE CARRIER PROFILE IF LETTERS/SYMBOLS ARE USED
3. PARSE SURFACE TOKENS
4. IF LETTERS ARE PRESENT, RECORD BOTH:
   a. alphabet ordinal value
   b. reduced root value
5. MAP ROOT VALUES TO THE NUMERICAL RING / CARRIER SEQUENCE
6. PRESERVE EACH LETTER'S ORDINAL REDUCTION PATH AS A PARALLEL SUBSTRUCTURE
7. READ ORDERED PATH LEFT → RIGHT
8. COMPUTE FIRST DIGIT SUM OF THE NUMERICAL RING
9. PRESERVE EVERY CANONICAL REDUCTION NODE
10. IDENTIFY FINAL ROOT
11. APPLY ZERO / REPETITION / REVERSAL NOTES
12. APPLY GLYPH EXTENSIONS ONLY IF REGISTERED
13. LABEL PROVENANCE OF EACH SYMBOLIC CLAIM
14. OUTPUT SURFACE + LETTER ORDINALS + ROOT CHANNEL + RING CHAIN + ROOT + INTERPRETATION
```

Canonical numeric output form:

```text
SURFACE :: ORDERED PATH :: REDUCTION CHAIN :: FINAL ROOT
```

Canonical letter output form:

```text
LETTERS
:: ORDINAL CHANNEL
:: ROOT CHANNEL
:: CANONICAL RING REDUCTION
:: FINAL ROOT
```

Example:

```text
7777 :: Knowledge→Knowledge→Knowledge→Knowledge :: 7777→28→10→1 :: Origin
```

Dual-value glyph example:

```text
GPGY
Ordinals: 7,16,7,25
Per-letter paths: G=7; P=16→7; G=7; Y=25→7
Root channel: 7→7→7→7
```

The ordinal channel is additive information. It does not replace `7777→28→10→1`.

## Mode B — Reverse engineer a formula from an intention

```text
1. FREEZE INTENTION IN PLAIN LANGUAGE
2. EXTRACT PRIMARY CONCEPTS
3. MAP EACH CONCEPT TO A CANONICAL ROOT
4. ORDER ROOTS BY THE DESIRED PROCESS
5. FORM THE SHORTEST CANDIDATE NUMBER / RING
6. COMPUTE ITS FULL REDUCTION CHAIN
7. INSPECT EVERY INTERMEDIATE RING AND FINAL ROOT
8. IF FINAL ROOT CONFLICTS WITH THE INTENTION, SEARCH SAME-CONCEPT ALTERNATIVES OR ADD A JUSTIFIED STAGE
9. COMPARE REVERSED / NEARBY CANDIDATES
10. SELECT THE FORMULA WITH THE CLEAREST DECLARED SEMANTICS
11. IF LETTERS ARE DESIRED, FOR EACH RING DIGIT:
    a. enumerate letters in that root family
    b. preserve each candidate's alphabet ordinal
    c. decode the ordinal pathway
    d. choose the candidate whose ordinal pathway best fits the intended symbolic role
12. VERIFY THE CHOSEN LETTER ROOTS REPRODUCE THE RING DIGITS EXACTLY
13. ANALYZE THE ORDINAL CHANNEL AS A PARALLEL SUBSTRUCTURE
14. APPLY REGISTERED GLYPH MEANINGS ONLY AFTER NUMERICAL VALIDITY IS CONFIRMED
15. FREEZE THE INTERPRETATION BEFORE ANY OUTCOME TEST
```

Number-to-letter selection example:

```text
required ring digit = 5
eligible:
E = 5 → 5
N = 14 → 5
W = 23 → 5

root 5 determines eligibility
ordinal 5 / 14 / 23 distinguishes the candidate pathways
```

## Per-ring letter rule

Every reduction ring may receive its own letter layer.

Example:

```text
R1 = 7777
R2 = 28
R3 = 10
R4 = 1
```

For each ring independently:

```text
ring digits
→ eligible letter families
→ chosen letters
→ letter ordinals
→ per-letter ordinal reduction paths
→ root values must reconstruct the original ring digits
```

A zero-containing ring requires a separately declared zero-symbol profile because A-Z has no root-0 carrier.

## Stop conditions

Stop and request a semantic decision rather than inventing a rule when:

```text
a concept maps equally to multiple roots and order materially changes the result
multiple eligible letters have different ordinal pathways and no selection criterion has been declared
a requested letter has no registered glyph-specific meaning but glyph-specific meaning is required
a numerical ring contains 0 and no zero-symbol profile has been declared
two symbolic profiles conflict
an outcome claim is being treated as proven solely because arithmetic is correct
```
