# FLOW — Meaning Attribution

FLOW ID: CORE-MEANING-ATTRIBUTION
STATUS: **CANDIDATE / VERIFICATION_PENDING**
DOMAIN: core
JOB: represent, separate, compose, and preserve intrinsic/extrinsic meaning claims without confusing symbolic meaning with factual or empirical authority
AUTHORITY: semantic representation and synthesis only
PARENT GOALPOST: supplied by calling domain/research/creative objective
UPSTREAM FLOWS: Domain Establishment, Research, Domain Library, Correspondence, domain-local meaning/rule Flows
DOWNSTREAM FLOWS: Domain Establishment, Domain Library, Correspondence, Story Reader/Writer, domain Flows
INBOUND PIPES: PLUMBING.md#pipe-core-domain-establishment-meaning
OUTBOUND PIPES: PLUMBING.md#pipe-core-meaning-library
SOFTWARE DEPENDENCIES: none

## GOAL

Let Xyool reason safely and explicitly about meaning-rich domains by distinguishing what meaning is claimed, where it comes from, how it changes with context, and what authority it has.

## GOALPOST

A meaning attribution is sufficient when object identity, intrinsic/extrinsic/composite type, system/framework, authorship, native meaning, context conditions, dependencies/conflicts, claim mode, and validation status are explicit enough for the requested job.

## INPUT STATE

Load as applicable: object/pattern; system/tradition/framework; source text/rule; contextual relationships; domain-library meaning objects; validation state; requested job.

## EVIDENCE

Meaning evidence may include primary tradition texts, living-tradition records, modern-system primary sources, scholarly/practitioner syntheses, user-declared frameworks, Xyool hypotheses, and learned patterns from validated cases.

Meaning provenance and empirical efficacy remain separate.

## PROCESS

IDENTIFY OBJECT / PATTERN
-> IDENTIFY REQUESTED CLAIM MODE
-> LOAD EXISTING MEANING OBJECTS
-> SEPARATE OBSERVED PROPERTIES / INTRINSIC CLAIMS / EXTRINSIC CLAIMS
-> IDENTIFY SOURCE / AUTHORSHIP
-> EXTRACT NATIVE MEANING
-> DISTILL SEMANTIC PRIMITIVES
-> IDENTIFY CONTEXT / RELATION CONDITIONS
-> IDENTIFY DEPENDENCIES / LINEAGE OVERLAP
-> PRESERVE CONFLICTS
-> IF SYNTHESIS REQUESTED: COMPOSE EXPLICITLY AND LABEL AUTHORSHIP
-> ASSIGN CLAIM MODE + VALIDATION STATUS
-> EMIT MEANING OBJECT

## GATES

Before intrinsic: a named source/system/user/framework makes that claim.

Before extrinsic: the relationship/context producing meaning is named.

Before composite synthesis: contributing meanings remain recoverable, contradictions are preserved, dependencies are explicit.

Before predictive/causal use: domain-specific validation gates apply.

## ADAPTATION

For conventional factual domains this Flow may be unnecessary. For symbolic/occult/metaphysical domains it may be a primary primitive. For creative domains unvalidated meaning may be generative material when creative-use status permits it.

## BOUNDARIES

This Flow does not prove metaphysical claims, convert symbolic tradition into empirical fact, erase source disagreements, invent provenance, grant predictive/action authority, or present user-created meaning as inherited tradition.

## FAIL-CLOSED CONDITIONS

Return MEANING_PARTIAL / UNKNOWN when identity, authorship, intrinsic/extrinsic classification, context, or requested authority cannot be supported.

## OUTPUT STATE

MEANING STATUS; MEANING ID; OBJECT / PATTERN; TYPE; CLAIM MODE; SYSTEM / FRAMEWORK; SOURCE / AUTHORSHIP; NATIVE MEANING; SEMANTIC PRIMITIVES; CONTEXT / RELATION CONDITIONS; DEPENDENCIES; CONFLICTS; VALIDATION STATUS; CREATIVE-USE STATUS; CANONICAL POINTERS.

## LEARNING HOOK

Later evidence may evaluate transfer across contexts, whether an intrinsic meaning is actually contextual, whether composite meaning overfits, whether semantic primitives help correspondence/prediction, and whether creative usefulness differs from empirical validity.

## SOFTWARE / HARD-LIMIT BOUNDARY

NONE — FLOWARE SUFFICIENT

## COMPLEXITY RULE

Prefer the smallest meaning representation that preserves source, context, contradiction, and authority.
