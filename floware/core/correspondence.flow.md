# FLOW — Correspondence

FLOW ID: `CORE-CORRESPONDENCE`  
STATUS: **ACTIVE / CANONICAL**

## GOAL

Transfer useful structure across domains without force-fitting source-domain rules.

## PROCESS

```text
SOURCE-DOMAIN RESULT
→ EXTRACT STRUCTURAL RELATIONSHIP
→ REMOVE LOCAL NOUNS/CALIBRATION
→ IDENTIFY TARGET-DOMAIN COUNTERPARTS
→ NAME IMPORTANT DIFFERENCES
→ FORM TARGET-DOMAIN QUESTION
→ BUILD TARGET-DOMAIN FLOW
→ TEST LOCALLY
→ RETAIN / MODIFY / REJECT CORRESPONDENCE
```

## BOUNDARIES

Do not automatically transfer:
- thresholds;
- coefficients;
- event priors;
- actions;
- evidence hierarchy;
- timing bands.

## OUTPUT STATE

- abstract invariant;
- target interpretation;
- transfer boundary;
- local falsification test;
- authority status.

## SOFTWARE / HARD-LIMIT BOUNDARY

`NONE — FLOWARE SUFFICIENT`


## MEANING / NOVELTY INTERFACE

When the source structure includes symbolic or meaning-bearing objects:
- use `meaning-attribution.flow.md` to preserve intrinsic/extrinsic/composite meaning distinctions;
- transfer semantic primitives only when the target domain defines a meaningful counterpart;
- do not transfer source metaphysical truth claims as target-domain facts.

For explicitly creative work, a correspondence may route through:
`PLUMBING.md#pipe-core-correspondence-novelty`

This allows remote analogy to become generative material without upgrading it to evidence.
